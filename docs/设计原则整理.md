# 设计原则

## 错误自报告

检测错误的层负责输出友好消息，不依赖调用方翻译。`validateConfig` 知道是哪个 provider、哪个 model 出问题，就应该它来说，而不是让 `main.zig` 去猜测。

## 调用方做管道而非门禁

当底层已自报告后，上层只需 `catch return` 统一放行，不应维护易遗漏的白名单。白名单的维护成本 = 每加一个错误类型 × 2 处改动，遗忘即漏。

## null ≠ 0

数据"不可用"和"值为零"语义不同，用 `?T` 区分。如 `cache_hit: ?u32`——`null` 表示非 DeepSeek 模型字段缺失（显示"缓存 N/A"），`0` 表示 API 返回了 0（显示"命中 0%"）。禁止用零值代指"无数据"。

## 前后端分离

Core 模块（`core/`、`io/`、`tool/`）永不 import render 代码。三个回调契约（`PhaseWriterCb`、`ToolDisplayCb`、`SystemPromptCb`）通过 `anyopaque` 上下文注入显示逻辑。换一个前端（TUI/Web）无需修改 core。

## 决策层持有持久化

Agent 循环只操作内存（session arena），不碰磁盘。App 层决定何时 `flush()`、何时 `rollbackTurn()`（中断/API 错误后回滚）。执行模块不应跨越持久化边界。

## 静态工具注册表

编译期数组，一个文件一行注册。LLM 看到的是从注册表自动生成的 OpenAI-compatible JSON schema。加新工具只需：创建 `tool/xxx.zig` → `registry.zig` 加一行 → LLM 自动知晓。

## compat 推断 + 覆盖

v0.1-0.2 用"TOML 盲拼"——provider 不解析、不判断、不硬编码 vendor 逻辑，`params_json` 直接拼接到 API 请求体。v0.3 起进化为 compat 层：`detectCompat()` 方按 URL 推断 thinking 格式、max_tokens 字段名、tool_choice 支持等 7+ 参数，用户在 TOML 中可通过 `compat` 字段覆盖推断结果。原则不变——provider 仍然不硬编码 vendor 逻辑，但不再是"瞎子"。

## Arena 统一内存

Session 消息由内部 `ArenaAllocator` 托管。所有 `append()` 自动 arena-dupe，`deinit()` 一次性释放。无散落 `free`，无悬垂指针。

## 原子写入

Session 写入用 temp + rename：先写 `.tmp` 文件，成功后再 `rename` 覆盖原文件。崩溃时 .jsonl 不损坏。

## 模型参数从官方文档

`context_window`、`max_tokens` 等模型规格从官方 API 文档获取，不凭经验编造、不从旧模型拷贝。违反此条的代价：131072（128K）硬编码在模板里，实际 V4 是 1000000（1M），用户用量显示错误长达多个版本。

## 自底向上验证

HTTP 层不通不建上层。`std.http.Client` 在 Windows 上 AFD.CONNECT IOCTL 超时不可用，发现后改用 curl 子进程。如果先建完 agent 循环再测 HTTP，全部上层代码白写。

## 单二进制零依赖

Windows 图标通过 `addWin32ResourceFile` 嵌入，curl 在 PATH 即可。无动态库、无运行时、无安装器。

## 显示在数据确定后

横幅、用量等显示应在数据最终确定后输出，不在中间步骤。`Config.load()` 只加载数据，`App.init()` 应用 `--model` override 后再打印横幅——否则横幅显示的是配置文件的默认值，与实际使用的模型不一致。

## 对比成熟实现补缺口

不自闭造车。命令行参数、输出格式、退出码行为——对照 opencode 等成熟项目逐项对比，发现 `--help`、`--version`、`--list-models`、退出码、stdout/stderr 分离等系统性缺口。

## 多模型兼容以锁非判断

不靠判断字段是否存在来切换状态（如 `reasoning_content` 存在就切思考阶段）。Qwen 每个 chunk 同时带 `reasoning_content` 和 `content`，导致每个 token 都触发阶段切换。用状态锁（`in_content_phase`）：一旦进入 content 阶段就不再切回 thinking。
